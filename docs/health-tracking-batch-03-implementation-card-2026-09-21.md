- 手记：妈妈/爸爸；文字与四种发生时间；折叠体温℃、浓/清鼻涕、重度/轻微咳嗽、有鼻音（喉音）、睡眠哄睡困难/夜醒多（多选）。选项可取消，未填不生成正常。文字或一项补充至少有一项即可保存。

## 最短可交付技术方案

1. 在现有 V2 内实现正式 React 页面和服务端读写入口，复用 `v2/lib/health/` 的事实、版本、来源和更正能力；不得使用应用 `getStore()` 或另造 localStorage 健康底账，不调用会按日期合并的旧 `persistCareEpisode`。
2. 本批以**独立文件账本适配器**完成端到端功能，单进程服务、文件锁；只对新建合成测试目录读写。显式配置私有数据根目录，缺配置默认关闭，禁止回退到现有账本/业务库/仓库公共目录。生产启用仍关闭，不声称文件方案已获上线许可。无需实现 Postgres repository、安装软件、创建 RDS 库或运行迁移。
3. 健康范围的服务端访问控制必须落地，不扩展全站登录项目。先确认现有可复用机制；无可用机制则实现独立健康会话：妈妈/爸爸各自服务端环境配置凭据，验证后签发短期 HttpOnly、SameSite 会话，生产 Secure；写入作者取会话而非请求自报。身份选项不能绕过凭据。所有页面数据、API 和原件检查会话，写操作检查同源/CSRF，禁止公共缓存；配置缺失即拒绝。凭据不入 Git、URL、日志，测试只用合成凭据。交付说明实际配置方式，不让 Teddy 再挑认证技术。
4. 新建录入生成稳定提交 ID，重试沿用**冻结的请求内容和发生时间**；主动“再记一条”用新 ID。更正、撤销、恢复等每实体维护修订号，在同一持锁写事务内比较期望修订号；冲突返回当前值和未提交草稿，用户明确选择后追加更正，不能静默覆盖。同请求重放不增殖。
5. 报告原件保存在私有文件存储并登记 hash/来源；缩略图仅预览，不能像演示代码那样仅存 120px 图。复用现有适用的媒体处理工具但不访问生产对象存储；上传边界校验真实文件类型/大小，限制合理且错误可理解，授权读取原件，禁止任意路径访问。原件写入和账本提交失败需可重试，不留下被当作成功的引用；图片方向与可读性用合成图验证。
6. 时间和单位在服务端校验；可疑温度提示核对并允许明确确认后保留数值与标记，不能将 34–43 当正常范围或强迫清空。所有保存动作只在持久提交成功后报成功。未提交敏感草稿本批优先留内存，失败不清输入，不额外做离线同步。
7. 读取按列表分页/详情组织，避免 React 渲染时调用应用全量存储；可复用健康投影缓存，不为这批造通用查询平台。新增症状/就医字段与 HEALTH-02 的有效值、更正和来源映射要清楚。
