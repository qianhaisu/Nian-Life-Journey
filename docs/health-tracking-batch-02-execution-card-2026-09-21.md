## 实现范围

1. **模型和兼容适配**：先检查 `v2/lib/types.ts` 的 RawSource/CareRecord/CareEpisode、`v2/lib/db/schema.ts` 和 repository。明确现有能力与缺口，最小扩展，避免另建一套无法接入 V2 的孤立底账。来源、观察事实、规范事实、就诊、病程有独立稳定身份及引用；字段保留来源、记录时间/发生时间、精度、角色、审核状态和版本。
2. **病程与候选**：确认关联、候选、同期背景分开；同日不同事件不合并，跨日同一病程可连接。24 条候选不得作为确认事实、治疗或次数统计。病程进行中、明确结束、结束未知、缺少近期更新分开。当前 `persistCareEpisode` 按同日 open 合并且清除来源故事关联，本次健康通路不能复用这两个副作用；保护既有故事、媒体及来源其他用途，保留现有防护。
3. **可重复导入**：CLI/服务默认 dry-run，报告新增、重复、版本变化、冲突、候选及拒绝原因。支持医院已核事实、微信增量和汇总稿转述层的显式适配；不重新 OCR 全部原件、不重新调用模型。新增输入按身份与内容版本判定，不能用分钟或日期当唯一键；相同 ID 内容变化保留版本，JSON/Markdown 差异和缺少强身份显式处理。
4. **更正和依赖更新**：人工更正有作者、时间、前后值和理由；后续自动导入不得覆盖。新增/更正影响哪些事实、病程、时间轴或分析版本要可查；只更新相关派生内容。医学辅助分析独立于事实层，保留事实快照、证据版本、适用条件与失效状态，本批实现关联/失效机制，不自动生成新诊断或新治疗建议。
5. **可审阅时间轴**：输出本地私有历史时间轴与差异报告，能从展示项追溯原件及更正；未知发生时间明确按消息记录时间展示，不伪装事件时间。区分处方、计划、交接、实际执行报告和疗程未知。可提供离线 JSON/HTML/Markdown 审阅产物；产品健康页面和手机录入仍属 HEALTH-03/04，本批不改首页或做 UI 重设计。

## 验收：先用合成数据验证，再对私有基线 dry-run

| 场景 | 必须观察到的结果 |
|---|---|
| 相同资料导入两次、乱序重放 | 业务事实/病程/引用不增殖；可解释的运行日志与业务内容分开，不能只比行数 |
| 同身份不同内容、跨格式增量 | 保留版本和独有消息，明确歧义；旧证据不被覆盖 |
| 新增一份病例或一批微信 | 差异仅含新增/真正受影响内容；无关历史全内容保持不变 |
| 人工更正后再次导入旧资料 | 更正仍为当前值，前值可追溯，旧摘要不复活 |
| 同日两种事件、跨日复诊、其他部位与呼吸道同期 | 不按日期直接归属；候选不计确认事实；关联校验检查具体目标身份，不能只查集合大小或关键词 |
| 问句/提醒/回忆/转述、未知日期、药物单位变化 | 来源与角色保真、未知不猜、单位参与校验，多消息证据链不丢 |
| 错引用、错病程、缺行、损坏输入 | 清楚失败，无部分写入；验证器异常转成可报告的失败，不能异常后继续计为通过 |
| 两个并发导入、导入中断与重试 | 唯一性/事务成立，无丢失更新；失败可恢复，人工更正不被竞争覆盖 |
| 与既有故事共用来源 | 故事关联、媒体和来源既有用途保持不变 |

通用规则用合成反例验证，不把具体家庭事实 ID、日期、疾病词表硬编码为通过条件。第一批脚本的全内容重建可作为回归证据，但不能替代以上增量、事务和并发验收。
