## R1-B 正文与医学证据随审核绑定（程序）

反例根因：采用只检查账本依赖，从不复核被审核内容本身。现在：

- 每版保存 `bodyHash` 与 `snapshotHash`；**采用与页面读取都会重新核验**正文哈希、快照哈希和结构/内容规则。提交后替换正文或快照、缺少采用人/时间/依据，都判为“不一致”：采用被拒（`integrity_failed`）；已采用的版本页面不再作为有效分析——内容不显示、措施撤下、病程提示待核，历史保留。
- 医学证据登记：每条来源登记已读正文（本地保存）的 SHA-256；分析把用到的每个证据 ID 绑定到登记条目的哈希。不存在的 ID 不能成为草稿；措施必须写明 `evidenceIds` 且属于本版引用；采用时与页面读取时重新核验：证据缺失、登记被修订、被撤回、保存的正文丢失或哈希变了 → 不能采用（`evidence_invalid`），已采用的保留文字并标“待重新核对”，措施同步待核。登记没有接通时一律视为未核验。这是结构化核验，不是字面拦截。
- 页面/服务新增可选 `HEALTH_PAGE_EVIDENCE`；命令新增 `--evidence`（analysis 各子命令、impact、page）。覆盖新分析的措施，不只旧 materials。
- 引用范围：`factRefs` 现在要求包含实际用到的记录——其他病程（用该病程的整体依赖哈希）、汇总稿转述、托班记录、未挂靠事实；`dataAsOf`（读到资料的截止日，程序要求覆盖所有被引用记录）与新增的 `episodeLastRecord`（本病程末次记录）分开；新增“托班记录”层，托班直接记录不再放进“汇总稿转述”。
