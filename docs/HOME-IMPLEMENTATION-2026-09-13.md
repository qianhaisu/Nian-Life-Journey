## 4. 首页接口契约（由数据轨落实为类型）

优先新增小型 `v2/lib/home-feed.ts` 作为稳定入口，内部复用已存在的 archive/upcoming 读取。具体函数签名由数据轨核对现有类型后在状态文件宣布；首次宣布后按兼容新增维护，不让页面猜字段。

| 数据块 | 必须携带的含义 |
|---|---|
| 时钟 | `today`、出生日期/当前年龄；与选中的故事日期独立，沿用 Asia/Shanghai 产品时钟 |
| edition | 期次标识、有效起止、所选候选标识；同一期不随刷新随机变更 |
| lead | 真实 eventId、href、标题、有限正文/摘录、日期、当时年龄；图片对象复用 MediaRef 等现有类型，带明确关联用途 |
| photo candidates | 仅返回当前可展示、可读的少量合格候选及选择依据；不向浏览器搬全库媒体或审核账本 |
| recent fact | 0–1 条，真实 eventId/href/日期/当时年龄/原有标题；不与主故事重复 |
| reminders | 默认重点一条、最多两条；区分 active、needs_confirmation、expired、done、cancelled/superseded；包含期限、来源证据与可展开详情 |
| unavailable | 区分材料为空、未完成提取、读取失败；未知不能推断为没有待办或全部完成 |

领域状态由数据轨决定，页面只做展示。首页读取复用一次现有 archive 结果；新增读取说明表、过滤范围、缓存和最坏调用数，避免重复整库加载。模型调用不能发生在页面请求里。

## 5. 照片轮换的产品规则

1. **先执行现有展示许可与关联门槛，再评质量。** 主故事配图必须满足最新的逐 eventId/mediaId 审核规则；独立封面必须满足其主体审核规则。不得用视觉评分、同日、trusted/confirmed 扁平集合绕过门槛，不改 visibility、不代写人工批准。
2. 近期候选默认最近 60 天内的现有合格材料。历史照片只有命中现有真实回看关系时才参与，不为凑配额随机抽旧照片；旧图始终带自己的日期和年龄。候选不足按有记录的降级策略选现有合格内容，不能拿不合格图补位。
3. AI 质量评价看可见互动/动作 35%、画面可读性 25%、可靠上下文 25%、近期差异 15%；这是初始产品参数，必须用实际候选复核，不能写假分数。不要按颜值或推断孩子内心打分。连拍/近似图分组，同一时刻先取一张。
4. 复用现有质量记录；缺失时实现可缓存、可幂等的有界评估步骤。首批仅处理最近 60 天内已经过展示门槛的候选，最多 30 张，输出候选范围、模型结果/降级原因和实际调用数。失败连续 3 次停止该批，不无限重试，不打开全局 Organizer 开关。
5. 同一期至少稳定 6 小时；同一家庭同一期的首页主图一致。刷新/返回不换，浏览期间不自动轮播。默认同图 14 天、同事件 3 天冷却；候选不足可以缩短冷却，但必须保留门槛和理由。
6. 自动期次切换需有可验证的选片历史或等效约束，不用 `Math.random()` 加 cookie 冒充稳定轮换。「换张照片」只在现有合格候选中显式切换；照片与事件不一致时标题/日期/链接一起更新。同事件内切换才允许文案不变。
7. 撤销展示资格立即优先于期次缓存；媒体失败回退到另一张仍合格的图。无合格图时保留真实文字，不画空照片框、不借别的故事照片。它是明确的材料不足状态，不能声称已满足图片覆盖。

## 6. 待办保鲜的产品规则

1. **退场不等于完成。** 清理首页资格，保留原始事项、来源和状态轨迹；没有完成证据不能自动 done。
2. 截止时间明确的沿用原意。没有期限的临时采购默认 48 小时；库存预测类提醒默认最多保持 72 小时新鲜度。起算点是原始事项的有效发生/提出时间，不是导入、AI 重跑或打开页面的时间。
3. 习惯提醒按 7 天关注周期处理，最多两个不同日期露出；无新观察不得由旧消息续期。
4. 接种/就诊等重要事项无结果时保留 `needs_confirmation` 摘要。未知日期显示时间待确认；不生成医疗期限、不推断已接种或必须补种。已预约事项过期也不能默默丢失。
5. 明确完成、取消、改期、替代各自保留证据；含糊回应不能关单；相同事项合并，只有实质新证据才能续期。重放同一来源是幂等的。
6. 每次首页读取均执行有效性过滤，后台归档延迟不能让过期琐事重新出现。重要项超出两条时用一个可展开摘要保持可达，默认布局不膨胀。
7. 实际核对当前已显示的陈旧采购、过期短期计划、近期档案核对提醒；私有证据保存到 NianlifeOps，Git 中只放脱敏结果与合成测试。
