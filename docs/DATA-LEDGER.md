## 2. 对账口径（每一项写清依据，不靠标签也不靠减法）

**微信身份**：精确层用仓库自己的去重键 `provider_external_id` = `canonicalMessageId`，输入含
conversation、sender、sentAt、type、text、附件摘要、**documentDigest**（= sha256(导出文件相对路径)）、
**recordOrdinal**（文件内第几条）。**这个键跨重新导出不稳定**——改文件名或在中间插入消息都会让 id 变。
`source_label`（conversationId）只取 `会话ID` + 标题 + 会话类型，**跨重新导出稳定**。
内容层用 (UTC 秒, senderDigest, sha256(正文), 媒体数) 多重集，**保留出现次数**。
**时间 + senderDigest 单独不能确证**：库侧 44,310 个弱键里 526 个覆盖了不止一条消息，
忽略标签后 1,212 个弱键上坐着 2,625 条消息。本账本任何"已存在"都不靠弱键。

**夸克身份**：原始文件内容的 SHA-256。HEIC 原件与转码件 checksum 不同是正常的，所以 HEIC 必须经
`quark-heic-converted-task-items.jsonl` 的 crosswalk（原件 sha → 转码产物 sha）追溯，**不能因为哈希
不同就判缺失**。

**库侧基准**：本轮可复用的库侧快照只有一份 —— 另一 session 于 2026-09-10 约 10:12 CST 经 SSH 隧道
从上述 RDS 导出的微信指纹转储（44,310 行 / 44,953 条消息 / 17 个 `conversation:*` 标签，
`captured_at` 上界 **2026-09-03**）。**它是否过滤了 `status='deleted'` 没有记录**，这一点限制了第 4 节
的两组重复候选。隧道当前已关闭（15432 端口不可连）。

   候选媒体的 checksum 是否已命中。旧快照只用于选候选，不用于写入前的最后判断。
2. **先 `--dry-run`**：确认 `--only` 的**索引**没有漂移（索引随目录扫描顺序变，历史上出过一次），
   并确认 `would import N message(s)` 与上表一致，不一致就停。
3. **预声明 → 写入 → 核对实际 delta**：`organizer_jobs` 必须 **+0**（导入不 enqueue Organizer）。
   重跑同一条命令必须 `created: 0`。完成条件的口径：`digest|since` 是完成键，窄 `--since` 不会把
   整个会话标记为已完成。
