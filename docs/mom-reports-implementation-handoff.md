## 五、发现并顺带修复的一个真实缺陷

`components/mom-report-growth.tsx` 最初按原型思路给 SVG 用了 `<title>`/`<desc>` 子元素做可访问名称。实测触发 Next.js App Router 的一个已知坑：流式 SSR 会把页面里任何叫 `<title>` 的元素当成 `<head>` 标题候选处理，导致服务端渲染出的 SVG `<title>` 是空的，客户端却是正常文字，产生 hydration mismatch（浏览器控制台报错，图表短暂重渲染）。已改成和站内既有 `GrowthChart` 组件一致的做法——直接在 `<svg>` 上写 `aria-label`，不用 `<title>`/`<desc>` 子元素。已验证 SSR 输出正确、hydration 无报错。

### 12.4a 第一次实现"不够保真"，返工的真正原因

第二轮第一次实现（六方面卡片、健康平铺、闪光时刻/外出小抄内容都还原了）截图发给 Teddy 后，反馈是"从你的截图看还不够保真"。核对后发现问题不在内容，在**视觉语言整体不对**：

- V1.3 的 `--max: 860px` 让整个页面在任何宽度下都是一条居中的窄栏（app 卡片式），`.mini-grid`/`.food-grid`/`.looking-ahead` 全部固定 2 列，desktop 唯一的媒体查询只是"手机再收紧一点"——即桌面样式本身就是这套窄栏样式，不存在"桌面版更宽"这回事。第一轮做成了 1120px 宽、42/58 分栏、三列网格的编辑器式桌面布局，宽度概念完全不同。
- V1.3 几乎每一屏都是一张浮起的白色/渐变卡片（`.card`，24px 圆角 + 阴影），返工前的版本用的是纯背景 + 边框的扁平分区，没有这层"漂浮卡片"的视觉重量。
- V1.3 的 hero 是"照片铺满 + 左上角徽章浮贴 + 信息面板负边距压在照片下沿"的经典构图；返工前是"文字块 + 独立照片"两段式布局，完全是另一种排版逻辑。
- 闪光时刻的图片背景：V1.3 对六张图统一用一个暖/冷渐变底（`linear-gradient(135deg,#fff6dd,#eef7ff)`），返工前的版本按每条内容自己的 tone 上色，背景色随内容变化——这是我自己发明的规则，V1.3 没有这条。

这轮把 CSS 按 V1.3 的实际规则逐条重写（最大宽度、卡片阴影/圆角、hero 构图、闪光时刻固定渐变底），只替换调色板基础色（纸色/墨色/线条色）和标题字体为站内 token，配色系统本身（五色调）、圆角值、阴影值、网格列数全部照抄 V1.3 的数值。
