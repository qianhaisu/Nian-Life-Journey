## 每次执行

1. 检查同步任务、最新归档和原始数据水位。同步仍运行则等待；失败则修复或报告具体断点，不能用上一次的成功回执代替本次成功。不得重启 Organizer，不调用旧的五阶段模型入口。
2. 在 `v2` 下运行 `node --import tsx scripts/editor/codex-editor.mjs prepare --out <本次私有目录>`。工具只读 RDS 和真实生产月稿，导出最近 14 天未覆盖、截至昨天的来源及内容版本。ECS 密钥默认在用户 `.ssh/nianlife-prod-ecs.pem`，可用 `ECS_KEY` 明确指定；不得复制到仓库或依赖 Downloads。
3. Codex 自己逐日看来源并写私有 `decisions.json`。文字只能描述有依据的事实；提议不写成已发生、照片评论不写成目击、成人健康和账户财务不写进孩子记忆。逐段填写当日 `sourceIds`，不猜发言人，不改已有日稿。
4. 用 `codex-editor.mjs apply --out <本次私有目录> --decisions <私有 decisions.json>` 重新核对数据库来源指纹、日期、人物、引语、敏感信息及已有日稿。它只生成候选稿与审核回执，不调用模型、不直接发布。
5. 通过来源审核的内容按照既有自动内容更新授权，使用带 expected SHA256 的 `content-install` 安装为新版本；安装前必须确认脚本具备内容版本比较和失败停止保护。现有私有运行目录 `C:/Users/teddy/Nianlife-runtime-main-aa499e7/v2/scripts/deploy-ecs-public.sh` 已有该保护。不要使用缺少版本比较的工作区改稿。旧月稿与数据库历史全部保留。
6. 直接打开生产月页、日页，核对日期和正文，再保存实际生效的内容版本、来源水位及健康回执。内容缓存需等待最多 300 秒，或使用已授权的内容刷新机制；HTTP 200 不能单独证明文字已更新。

## 同一轮检查的其他模块

- 照片和视频：新微信媒体默认 private。Codex 直接看原图及必要的视频帧，检查来源、主体、隐私和授权；只有明确允许公开的画面才调整可见性并进入公开候选。新增审核行真实记录 `provider=codex` 和审核证据；不冒充旧 GLM 结果，不覆盖人工决定。未看到的画面不自动通过。只运行纯验证和合并代码。
- 旅行：核对最近来源与已有旅程，区分已发生、确定计划和提议。线上已有从已发布日稿标题提取明确出发/到达的逻辑，但可能漏掉正文行程。新的 `travelRecords` 月稿字段允许 Codex 在直接核实孩子同行、真实地点和起止后，追加完整 Trip 与 `reviewStatus=approved`、`reviewedBy=codex`、`visibility=public`、`childPresent=true`、`reviewedAt` 和非空 `sourceFingerprints`（每条含原始来源 id 及内容 SHA256）。核验每个来源仍在库内且未变，将月份放在出发日期所在月；已确认的整段旅程可替代同次自动单日记录，不覆盖人工旅程。没有明确新出行就记录“无新增已发生旅程”。首版读取修复须经人工批准部署；该版本上线后，新记录随版本化月稿内容安装生效。
- 提醒：首页已有待办继续显示。Codex 直接核对明确的日期、事项、来源和指纹；更新采用现有追加审核/历史记录机制，不运行 GLM/DeepSeek 提取器。不把资金讨论或泛泛建议变成公开提醒。
- 首页轮播：复用已审核素材和现有评分。新增素材由 Codex 直接审核；不运行旧 `home-carousel-rescore.mjs` 模型脚本，不把缺少评分冒充成评分成功。

## 结果与失败

每次在私有目录保存来源水位、各模块结果（updated / no_change / blocked）、内容版本、来源证据与线上核验。未变时安静结束；实际更新、失败或确实需要用户操作才通知。余额、网络、导出或工具失败属于基础设施问题，不能永久把一个有素材的日期标成 skipped / held。

代码修改只提交本轮文件到当前 `main`，先通过类型检查、Lint、相关测试和生产构建再 push；共享工作区的其他暂存与未提交修改保持原样。自动内容安装与应用代码部署分开记录，不能把 push 写成部署成功。
