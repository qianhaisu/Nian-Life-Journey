## A. 草稿与重试：页面不能承诺保留却丢失

涉及 `record-app.tsx` 的 RecordApp、NoteForm、VisitForm、Detail。

- 父组件按 tab 条件挂载表单，切换标签即卸载，文本/图片/entryId 都丢失；401 调用 onLost 后也卸载。用户填到一半查看已记录，或保存时会话过期，都会丢掉内容。这与仅“刷新丢失”的已披露限制不同。
- submit 每次从当前可编辑 state 重建 payload，只有 ID 稳定，完整请求未冻结。服务端已提交但响应丢失后，修改文字再点重试会复用旧 ID 提交异文，返回 409；当前页没有可靠的恢复路径。归属与冲突“用我的”动作又在每次点击生成新 requestId，不能可靠重放响应丢失的那次操作。
- 医院/科室选“其他”填文字后切回固定选项，隐藏的 other state 仍发出；后端 pair 明确拒绝，家长会遇到看不见的字段阻止保存。

修正：草稿和提交状态由不会随标签切换卸载的层持有（仍只在内存，不新增离线同步），同身份重新登录可恢复；显式退出或切换身份不得把上一个人的草稿自动归给另一个人。提交后冻结完整请求及 ID；网络结果不确定时先重放/查询这次结果，再允许作为新记录或更正继续。所有写动作沿用同一逻辑。切回固定医院/科室时清除或不发送隐藏 other 字段。

验证只补一组精简浏览器场景：填图文切标签返回、模拟401恢复、提交成功但丢响应后重试、其他→固定选项保存。覆盖手记与就医共享逻辑即可，不重跑整套原型。
