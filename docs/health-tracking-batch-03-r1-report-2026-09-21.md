## A 草稿与重试（`app/health/record/record-app.tsx`）

- **草稿不再随标签或会话丢失**：三个入口的表单、已记录列表和更正抽屉都常驻挂载，切标签只是隐藏面板；401 只把整个工作区藏到登录页后面。**同一位家长重新登录**，图片、文字、所选时间、正在填的更正都恢复；**换另一位家长登录得到全新的空白工作区**，登录页明确提示“上一位的内容不会带给你”；**显式退出**直接丢弃草稿。草稿仍只在内存，刷新即丢，没有新增离线同步。
- **冻结完整请求**：点保存时把完整请求（提交 ID + 内容 + “刚刚”的时间 + 实际图片文件）冻结，表单随即锁定。结果不确定（无响应、网关错误、无编码的 500）时页面说“结果不确定”，“重试”原样重放，服务端返回已保存的那一条（提示“已经保存过了，没有重复”）；想改内容只能明确选“放弃这次，改内容后作为新记录”，那时才换新 ID。明确未保存的失败（校验、401、存储失败）则解冻，内容仍在，可改可重试。
- **更正、撤销、恢复、“用我的草稿”同一逻辑**：每个动作把请求 ID 与请求体冻结，结果不确定时重放同一请求（服务端按请求 ID 幂等），或“放弃这次操作”后先看当前记录——如果它其实已生效，再改会得到“刚刚被改过”而不是覆盖。
- **隐藏的“其他”文字**：改选固定医院/科室时清空对应的“其他”文字，并且只在选着“其他”时才发送（手记外的就医录入与更正抽屉都改了），家长不会再被看不见的字段拦住。
