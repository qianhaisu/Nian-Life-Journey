# 协作运行规则：唤醒、交接、成本、效率

> 最新覆盖：角色与唤醒按 `DIRECT-COORDINATION.md`，移除 Cowork 层；本文件其他费用、短交接和效率原则继续有效。

2026-09-07 总指挥定稿。角色和权限沿用 COORDINATION.md；本文件的频率是目标配置，实际启用必须有调度器 ID 和触发回执。不能把规范当作已部署软件。

## 1. 唤醒与轮询

| 角色/组件 | 工作期间 | 空闲或被外部条件阻塞 | 已落地/待验证 |
|---|---|---|---|
| Codex 总指挥 | 当前交互中及时收件；后台每 30 分钟复核 | 无待审核项时降为每小时 | 本线程 heartbeat；不唤醒其他角色 |
| Cowork | 每 5 分钟收件、派单、初审 | 两轮无变化退到 15 分钟，再退到 30 分钟 | 须验证自身调度器及本机文件访问 |
| Code A/B/C | 任务开始/阶段完成/结束时收件；等待依赖时每 5 分钟 | 两轮无变化退到 15 分钟，再退到 30 分钟 | 各轨自行确认本机会话调度 |
| 可选本机轻量检查器 | 每 60 秒只读入箱版本/mtime，变化才投递 | 无变化不调用模型 | 尚未实现；先验证受支持的投递 API |

- 每角色最多一个有效调度器/任务执行者。恢复时先查询旧调度，不能重复创建。收到消息即 ACK 唯一 ID；ACK 游标只在消息已成功处理后推进。无变化不写出箱、不 commit。
- 每次只读当前看板和上次消息 ID 之后的增量；历史可能追加在顶部或尾部，以 ID 去重，不能只用文件尾行号。STATE 顶部限 60 行，HANDOFF 限 80 行；指令版本没变就不反复读完整协议。
- 文件更改只说明有消息。验收必须包括：首次自然定时触发、空闲后再次自然触发、压缩/恢复后重建调度。PING 只允许写回 PONG 和时间，不跑生产、不修改应用。测试未过前标记“可通信但不可无人值守”。
- 等待超时按接收方已确认的周期计算；两次计划执行均无 ACK 才判失联。调度存在延迟且繁忙时可能延后，超时不代表原任务已停止。先查占用再重派，生产操作绝不自动重试。
- Claude Code 本机版本已核对为 2.1.263，可由各轨检查自己的 `/loop` 或 Cron 工具；官方说明这类任务依赖运行中的会话、会过期，新会话需重新检查调度。不能把在终端执行一串 `/loop` 当作向已存在会话成功注入。
- Cowork 官方已提供 Scheduled 功能，应检查当前会话实际工具/账号能力，不能仅凭“当前是手动启动”就认定不能调度。内置频率不支持 5 分钟时记录实际最小值，不伪造。云端任务仍须验证能访问此本机仓库；本机文件桥接需要桌面端在线。
- 没有可用受支持投递方式时只保留低频原生调度，报告缺口；不引入五个常驻模型空转进程、不冒名启动替代 Cowork。

## 2. 上下文与交接

- 大上下文可能增加每轮输入负担，但额度计量还受模型、缓存、推理和工具输出影响，不承诺固定节省比例。先减少无意义轮询、完整历史和长日志。
- 在阶段完成时主动交接；可见 context 指标达约 60% 时准备 HANDOFF，约 75% 时在安全节点压缩。这是项目操作阈值，不是平台限制；看不到指标就按阶段/长输出批次交接，不伪造百分比。
- 每个 HANDOFF 保留：角色、当前任务 ID/状态、最后收件 ID、基线及交付 SHA、未提交修改归属、占用与运行进程 ID、明确授权出处、禁止事项、证据位置、未解问题、下一条动作、调度 ID/下次检查点。
- 原始会话不是唯一记忆。权威事实进入文件，长日志留在本地证据文件，仅传摘要；绝不携带凭据、家庭原文或整份备份。旧结论被新证据推翻时写明 supersedes，不把历史冲突揉成一个确定事实。
- Claude Code 可在交接后使用自身支持的压缩功能，保留权限/未完任务/资源占用/失败证据。跨新会话交接只有明确授权后才创建；本次没有授权 Codex 新建任务线程，不擅自建线程或分支。
- 数据库备份/恢复等临界阶段不清空状态或迁移所有权。新会话先核对实际进程和产物，确认接管后再行动，旧会话停止消费同一任务；压缩或恢复后重新验调度而不是假设还存在。

## 3. 防止再次失控消费

- 总体放大模型：单次返回字节 × 页面/任务数量 × 重复次数 × 并发数。不能只看库大小、查询时长或扫描行数；生产只读同样会产生出站流量。
- 构建、测试、预览、唤醒探针与日常状态轮询不连接生产数据库。使用无生产凭据的隔离目录、合成数据/本地恢复库；暂停 worker/站点的既有决定继续有效。不得把线上访问当作消息系统的心跳。
- 任一收费任务卡写清：服务/操作、明确授权出处、单执行者、最大操作次数/并发、数据量估算依据、时间上限、停止条件、真实用量如何读取。空白预算只允许离线分析，不授权无限运行。
- 既有正式备份范围不扩大：两份全量备份 + schema-only 与已批准核验；不因压缩、重启或交接重置计数。首次失败停止新增尝试，先定位；断点及已消耗预算跨进程保留。之前反复诊断的轮数不抹掉。
- 优先供应商硬上限；告警不是硬上限。迁移报告记录过 Vercel 托管项目不能设置 Neon quota 的问题，未验证可用之前不得宣称已设硬闸，不改计划/余额/额度进行“测试”。限制值单位、周期与 0 的含义必须查实。
- 任务级超时/次数上限只是降低风险，不等于美元硬上限，也不覆盖其他进程。无法得到及时计量时不自动续批。停止只针对本任务受控进程，不杀所有 PostgreSQL 或其他会话。
- SQL 按 ID/月份/分页和必需列读取；全量导出仅限获批备份任务。构建期入口、ISR、Cron、手动脚本都必须审计，不能只修一个函数。
- A 出预算与备份状态证据；C 检查构建/调度/媒体出站路径和可执行的上限方案；Cowork 交叉初审，总指挥确认可验证的保护层后才允许下一阶段。尚未部署的保护统一标“待实现”，不写“已防止事故”。

## 4. 执行效率

- 每轨最多一个 running 任务；Cowork 优先派可独立执行的工作，不让离线清单等备份、也不让所有人重复读完整事故报告。
- 普通任务 ACK 一行，完成时一份短证据摘要；阶段内只在阻塞、范围变化或超过预期时汇报。无变化不写心跳；正式里程碑沿用产品八原则验收，纯通信 ACK 不冒充产品里程碑。
- 执行者完成检查，Cowork 查范围与关键证据，总指挥复核关键风险与结论，不把每一层审核变成同一套全量测试的重复运行。代码/依赖/配置及环境未变化时可引用同一源码树的已通过检查证据，不能把过期证据冒充新测。
- 全量检查按 AGENTS 要求执行，生产构建只在隔离环境。测试失败不全仓顺手修；记录原失败、复现情况与归属，避免踩别轨文件。
- 总指挥对 Teddy 常规每小时汇总一次；只报已验收结果、阻塞、下一步及需用户决定的事项。费用失控、数据损坏、错误发布立即报告；不能承诺休眠/离线时也实时发现。
