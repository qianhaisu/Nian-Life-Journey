# Nianlife 访问统计（本地管理后台）

## 一、架构设计与隐私保护

访问统计严格遵守隐私与安全规则，区分**线上日志采集**与**本地统计后台**：
- **线上日志采集**：由公网入口 Caddy 直接记录访问日志至容器具名卷 `/data/log/access.log`（保留 50 个轮转归档文件，最长保存 90 天）。Caddy 直连网卡监听 80/443，真实客户端 IP 直接取自底层 TCP 握手连接，不受客户端伪造的 `X-Forwarded-For` 等转发头干扰；Caddy 过滤器彻底删除 `Cookie` 与 `Authorization` 等凭据头；默认不记录 POST 请求正文；保留完整 User-Agent。
- **本地统计后台**：**仅在本地 Windows 运行**，默认仅监听 `127.0.0.1:4000`。不部署至公网域名，不在网站上增加任何后台入口或公开统计接口。
- **凭据与存储安全**：本地通过安全 SSH 直连 ECS 读取并增量拉取日志，私钥严格读取本地已有凭据（`~/.ssh/nianlife-prod-ecs.pem`），不在仓库中保存任何密钥；本地数据存放在 `v2/.data/stats.db`（SQLite WAL 模式），已被 `.gitignore` 保护。

## 二、IP 归属数据来源与隐私保障（零外部网络调用）

- **归属解析模式**：**100% 本地离线解析（Offline-Only）**。
- **是否调用外部服务**：**否**。系统内置离线网段映射引擎与本地 SQLite 缓存，不依赖、不调用任何第三方公网 IP 解析 API。
- **是否向外发送完整 IP**：**否，绝不外发**。所有 IP 匹配均在本地内存中完成，任何客户端 IP（包括 IPv4 和 IPv6）绝不向任何外部服务器发送。
- **地理归属性质说明**：归属数据代表该 IP 网段在运营商（如中国电信、中国移动、中国联通、广电等）层面的**网络接入地 / 网段注册地**（省市与 ISP），**绝非用户的个人精确物理居住地址**。

## 三、历史数据与统计口径技术边界

### 1. 历史打码 IP 与 UV 解释
- **历史数据覆盖**：`2026-10-12 14:01:14 CST` 至 `2026-11-17 22:54:32 CST`（共 36 天，91,704 条原始记录）。
- **打码与去重限制**：在此期间，线上 Caddy 按 `/16` 掩码打码（如 `125.119.0.0`），且 User-Agent 完全被剔除。历史丢失的完整 IP 和设备信息**不可恢复，绝不主观推测或伪造**。
- **UV 口径重要提示**：在打码历史阶段，统计的**不是真正独立物理 IP，而是独立 /16 来源网段数**！同一城市同一运营商 /16 网段下的多位访问者会被合并计数，因此**历史 UV 显著低于实际物理设备数**。
- **新版采集生效时间**：**2026-11-17 22:54:33 CST** 起生效，开始记录完整独立 IP、精确时间（秒）与完整 User-Agent。

### 2. 页面浏览量 (PV) 判定标准
- **请求方法**：必须是 `GET` 请求。`HEAD` 请求仅获取响应头，用于爬虫或探针状态核验，**已被严格排除在 PV 之外**。
- **响应状态**：仅统计成功响应（200 / 304 / 206）。
- **资源过滤**：严格排除静态资源（`.js`, `.css`, `.woff2`, `.png`, `.jpg`, `.mp4`、`/icon` 等）、Next.js 预取请求（识别 `Next-Router-Prefetch: 1` 或 `Purpose: prefetch` 头）、健康检查探针（`/api/health`）、后台 API 与安全探测。
- **敏感查询参数脱敏**：采集管道自动检测并在入库前对 `token`, `auth`, `key`, `secret`, `password`, `code`, `ticket`, `session`, `phone`, `mobile` 等敏感参数实施 `[REDACTED]` 脱敏替换；页面路径 `path` 永远只保留纯净路由。

### 3. Next.js 客户端路由、缓存机制与服务端日志的原理性边界
- **Next.js 客户端 Router Cache 影响**：
  Next.js App Router 具有客户端内存路由缓存。用户在浏览器标签页内点击 `<Link>` 访问已在内存中缓存的页面时，由浏览器内存直接渲染，**根本不会向服务器发送任何 HTTP 请求**。
  纯服务端访问日志（Caddy log）物理上无法捕捉这部分纯客户端内存页面切换。
  当缓存失效或访问未缓存路由时，Next.js 发起带 `Rsc: 1` 的请求，服务端日志会正常识别并提取目标路径。
- **浏览器 HTTP 强缓存**：
  若浏览器命中本地磁盘强缓存，同样不会产生服务端网络请求。
- **统计定位**：服务端日志 PV 统计反映的是**网站真实的回源访问量与服务器实际承载负荷**，而非前端埋点 SDK 的视图渲染次数。
- **访客分类命名**：不使用“真实人类访客”标签，而明确命名为**“常规页面访问 (排除已识别爬虫)”**。系统仅能根据 UA 与行为特征排除常见爬虫与自动化脚本，未特征化的隐蔽脚本仍会归入常规请求，无法承诺 100% 区分人与脚本。

## 四、本地启动与使用方法

在项目 `v2` 目录或根目录运行：

```bash
# 启动本地统计后台（默认端口 4000）
cd C:\Users\teddy\Documents\Nianlife\v2
npm run stats
# 或 python v2/scripts/stats/server.py 4000
```

打开浏览器访问：
👉 **http://127.0.0.1:4000**

- **增量同步线上数据**：在后台界面点击 **「🔄 增量同步线上数据」** 按钮，或在命令行运行 `npm run stats:sync`。
- **IP 穿透下钻**：在表格中点击任意 IP，即可查看该 IP 在选定时段内的访问频次、网络归属运营商、首末访问时间及访问过的全部页面流转。
