# ECS 发布保留规则

2026-09-19 Teddy 明确要求长期执行：当前线上版本 + 最近两版回滚，不需逐次提醒或确认。此维护授权不代替新版本的发布授权。

同一镜像的重复回滚容器不占两个版本名额；按镜像 ID 去重后保留最近两个不同于当前的版本。Codex 入口见根目录 `AGENTS.md`，Claude Code 入口见 `.claude/rules/ecs-retention.md`。

发布入口 `v2/scripts/deploy-ecs-public.sh swap <short>` 在新容器健康后自动清理。构建与切换使用同一 ECS 文件锁；不得绕过锁并行构建。清理脚本默认只输出计划，`--apply` 才执行。失败发布不清理，清理失败返回非零，保留已上线服务并报告维护失败，不自动回滚健康服务。

回滚候选仅为 `nianlife-diag-web-pre-<sha>-YYYYMMDD-HHMMSS`，按名称内切换时间倒序保留两份。存在运行中的候选或不符合应用镜像命名的候选时中止。删除仅使用明确的已停止容器 ID，不强制删除、不删除卷。应用镜像只清理 `nianlife-web:<十六进制 SHA>` 中不被任何容器引用的标签；其他仓库镜像不动。最后清理悬空镜像与未使用构建缓存。

当前容器须 healthy，健康 API 的 SHA 须与镜像标签匹配，首页须返回 200。清理前后验证当前及保留回滚的 ID、镜像和挂载未变。磁盘释放量以文件系统测量为准。输出不得包含环境变量或凭据。

数据库、媒体、妈妈月报、环境文件、证书、数据卷及 Git/发布记录永不属于本规则清理范围。历史部署目录与上传包也不由该脚本删除。出现异常或磁盘不足时由执行者处理并报告，不静默扩大删除范围。
