## 1. 视觉方向与 skill 使用

- **用户参考图是时间轴的视觉标准**，优先于任何通用风格推荐。整体改为扁平、白底、深蓝文字，去掉厚阴影、大图标圆盘、弯曲连线和大面积米色卡片。可爱来自小图标、配色和细节。
- 实际使用本机 skill `.github/skills/ui-ux-pro-max`（运行 `scripts/search.py`）：
  - `--design-system` 推荐 Claymorphism + 粉色系（厚阴影、粗边框）：与参考图冲突，**未采用**。
  - `flat-design`（style）：无阴影/渐变、1–2px 描边、4–6 个纯色——**采用**为全页基调。
  - `Color Only` / `Color Contrast`（ux）：颜色之外必须有文字或形态；文字对比 ≥4.5:1——**采用**：图例全部带文字，“只知开始”用渐隐形态，“未归入病程”用虚线框，正文用深蓝。
  - `Target Size (Minimum)`（ux）：Web 点击目标 ≥24px——**采用**（节点、附件、折叠标题都 ≥32px）。
  - `Horizontal Scroll`（ux）：整页不横向滚动——**采用**，只有时间轴容器可横滑。
  - `Trend Over Time`（chart）的可访问性兜底：图例直接标注、可读的详情列表——**采用**为节点详情。
  - `Healthcare App`（color）的青色主色、`Soft Rounded`（typography，Varela Round 不含中文）、`Chinese Simplified`（Noto Sans SC 需联网）——**未采用**：颜色以参考图为准；原型不联网，用系统中文字体。
  - 折叠组件（accordion / progressive disclosure）两次检索无有效命中，按 skill 规则改用通用默认：原生 `details` + 标题旁可见的“展开/收起”与箭头。

## 3. 健康页

顶部：标题与“记一笔”；下面三段跳转：健康时间轴 / 病程分析 / 后续措施。

### 3.1 健康时间轴（按参考图还原）

- **构成**：居中的深蓝标题“健康时间轴”+ 日期范围副标题；右上浅灰底图例框（手机放到轴下方）；月份刻度和细竖线；横向圆润色带；从真实日期处**垂直向下的细直线**、深蓝小圆点；紧凑的日期；淡色底短标签（有症状淡红、就医/检查淡蓝、明确无症状淡绿、未归入病程白底虚线框）。
- **小型形象图标**：发热用小火苗（与参考图一致），就医用小医院十字，检查用小试管；其他事件用深蓝小圆点。图标约 18px，不加圆盘。
- **色带**只画记录本身写明的时间段：有症状（红）、明确无症状（绿）、只知道开始（红色向右渐隐）。没有记录的时间是**浅灰底**，图例写“没有记录（不代表健康）”，不用斜纹，不压过事件。零散节点不连成区间，没有记录不当作健康期；不显示天数、比例或结论。
- **节点排布**：直线始终在真实日期处。相距太近的事件合成一个节点，用日期范围标注（如“9/12–9/14”，参考图也有这种写法），点开后逐条列出；放不下时用第二层（直线更长），第一层标签不压第二层的直线。
- **全程概览**（轴上方，紧凑）：完整跨度的月份、色带和事件小点，方框标出下方详细轴当前位置；点击/拖动概览，详细轴跟随；横滑详细轴，方框同步。
- **桌面**：“全部”范围下完整时间轴一屏显示，不需要横滑，版式与参考图一致。**手机**：不缩小整张图（日期 13px、标签 12px、月份 16px），详细轴在自身容器内横滑，默认停在最近；有 全部 / 近3个月 / 近1个月 三档和左右箭头。
- **详情**：点节点显示日期、内容、来源类型（家长记录 / 医院资料 / 汇总转述）与出处、附件、所属病程链接；只写了开始的记录说明“结束不明”。
- 身份不确定的资料放在时间轴下方的折叠项，不在轴上、不用于分析。资料不足时如实缩短覆盖范围；分析过期时提示“最近一条是 X 日，之后已 N 天没有新记录”。

### 3.2 病程分析

类别（呼吸道、发热、烫伤）和具体病程两级**默认折叠**；病程行显示日期范围（结束未知写“未知”）。展开后只有三部分：

1. **发展经过**：按日期的关键变化；结束已知写“结束 X 月 X 日”，未知写“结束：时间未知”。
2. **病程总结**：一两句话，重要的不确定性写进这句话里。页面没有“依据”入口。
3. **就医记录**：每次只显示**日期、医院 · 科室、处方、报告附件**。
   - 不显示“家长确认用了”，也不另起一行“实际用药”；底层的家长确认使用数据保留，只是不在这里展示。
   - 报告是附件按钮，点击打开附件页；没有就医的病程写“这次没有就医记录”。

发热类别中关联到呼吸道病程的体温只作关联入口并写明“不重复计数”；资料不足时只保留经过和就医记录。

### 3.3 后续措施

只有两组，**两组都默认折叠**，点击标题展开；标题旁有“展开 / 收起”文字和箭头，并显示项数。

- **观察与护理**：量体温、夜间垫高上半身、看烫伤处（写明最近记录日期）等。
- **就医安排**：条件性就医建议放首位（标“建议 · 遇到才需要”）；已确认预约只来自家长写下的预约或医嘱中的明确日期（标“已确认预约”）；其他建议标“建议 · 尚未预约”，不会自动变成预约。

每项可点回对应病程；页面没有“依据”入口，也没有其他分组。底部一句：辅助整理，不是诊断，不能代替医生。

## 4. “记一笔”与 HEALTH-03（保持）

“记一笔”打开 HEALTH-03 已验收的独立工作区（爸妈手记 / 就医 / 已记录），不重做表单；全屏盖住站点菜单，任何时刻只有一排底部导航。HEALTH-03 保存并更正后的有效内容是本页“家长记录 / 医院资料”的来源之一；健康页本身只读。

## 5. 医学文案与数据边界

原型文案是代表性示例，展示**不等于完成医学审核**；正式接入前须核对来源与适用条件，示例阈值（体温、天数）不是固定医学规则。页面不显示“依据”，但底层来源、版本、审核信息、生成时间和适用条件必须保留、可追溯。

## 6. 正式实施依赖（确认后另发实施卡）

1. **读取访问保护**：页面、API、附件、缓存受保护；确定与 HEALTH-03 `hr_session` 的关系。
2. **事件与区间数据**：事件（类型、时间精度、来源层级、原件定位）与“记录本身写明的区间”（有症状 / 明确无症状 / 只知开始）；区间不能由节点插值。需核对 HEALTH-01/02 底账字段。
3. **病程、类别与就医记录**：日期范围（结束已知/未知）、每次就医的医院/科室/处方/报告附件；家长确认使用数据保留在数据层但本页不展示；发热与呼吸道的关联、未归入病程、身份不确定三种状态。
4. **总结与措施来源**：HEALTH-M01 的已审核结构（结论、来源、版本、审核状态、生成时间、适用条件、失效规则）；页面不调用模型。过期阈值待定。
5. **预约数据**：已确认预约与首页健康提醒需要结构化的预约/复查日期入口。
6. **站点改动**：主菜单三项改四项；提醒区加“生活 / 健康”标记；概览联动需真实设备验证。
7. **上线前**：真实手机与读屏、深色模式、代理/HTTPS、多进程、真实数据库。

**与参考图的有意差异**：
- 没有记录的时间是浅灰，不像参考图那样整条着色，因为不推断健康或患病。

- 多一条全程概览。
- 不含参考图的统计与结论区。
