## 1. 全站导航与首页

- 主菜单固定 **首页 / 记忆 / 健康 / 妈妈月报**，手机只有一排底部菜单，桌面为顶部菜单。
- 首页保留主照片、题签和现有“近期提醒”区。提醒每条带类型标记：**健康** 用圆润的红色十字图标 + “健康”文字，普通提醒仍标“生活”（叶子图标）。不新增健康仪表盘。
- 健康提醒只来自明确的预约或复查安排（示例：复查血常规，日期、时间、医院）。点开进入健康页的“后续措施”。不从历史处方生成用药提醒。

## 2. 健康页：三个部分

页面顶部是标题、“资料截至 X 日”和“记一笔”按钮，下面一条三段跳转栏：**健康时间轴 / 病程分析 / 后续措施**（吸顶，跟随滚动高亮）。不设首页式的卡片堆叠。

### 2.1 健康时间轴

参考“连续时间带 + 事件节点”的表达，但不采用其医学结论、统计和红绿二分。

- **覆盖范围**：开头写明“已有资料覆盖 X – Y；之前没有资料”。时间带只画这一范围。
- **时间带三种状态**（图例常驻）：
  - 有症状记录：实色（暖赤陶）。
  - 明确无症状记录：实色（灰绿），只在有记录明说“没有不舒服”时画。
  - 资料未知：斜线底色，是时间带的默认状态。
  - 另有“起止不明”虚线：只写了起点、没写结束的记录，仅画一小段虚线，不延长填满。
- **色带只来自记录本身写明的持续时间**（如“妈妈事后记录：这三天一直在咳”）。零散节点不连成区间，无记录的时间不当作健康期，也不推算持续有症状。没有可靠区间依据时不显示患病天数或比例（原型有专门检查）。
- **节点**：症状、体温、就医、检查、明确好转五类图标；已确认是张年但尚未归入病程的节点用虚线圈。距离很近的节点合成一组（显示条数），点开后在下方逐条切换。
- **选中事件**在时间轴下方展示：日期、类型、内容、来源类型标签（家长记录 / 医院资料 / 汇总转述）、时间精度说明（是时间点还是有覆盖范围）。“查看来源”展开来源出处和所属病程；医院资料另有“看原图”入口。
- **手机**：时间轴左右滑动（不是把桌面大图缩小），默认停在最近；提供 全部 / 近3个月 / 近1个月 三档范围和左右箭头；选中事件显示在下方，不弹层。桌面同样横向滚动，不缩小成不可读。
- **身份未确认的资料**另行放在时间轴下方的折叠项里，明确“不在时间轴上、不用于分析”，不混入孩子事实。
- **资料不足 / 过期**：资料很少时时间轴只显示已有几条，覆盖范围如实缩短；过期时顶部提示“最近一条是 X 日，之后已 N 天没有新记录”。

### 2.2 病程分析

按类别分条展开（示例：呼吸道、发热、烫伤）。每个类别下按次列出病程，同类不同次分开。每次病程展开后固定四块：

1. **发展经过**：按日期的短时间线，每条带来源标签。
2. **最近有记录的状态**：注明日期，并直接写“哪些没有记录”，不把无记录当好转。
3. **分析与依据、不确定之处**：分析可展开依据，依据分为“支持 / 不确定 / 医学依据”，个体事实与医学资料标签分开（家长记录 / 医院资料 / 汇总转述 / 医学资料）。汇总转述只作线索，不作依据。
4. **相关就医记录、检查报告及原图入口**，以及“在时间轴上看”。

规则：
- **处方与实际用药分开**：处方是医院资料；“实际使用”单独一行，没有记录就写“没有记录，不能认为正在服用或已服完”。
- **发热与呼吸道**：发热类别里，关联到呼吸道病程的体温记录只显示为“关联入口”，明写“同一次生病的表现，不再另算一次发热”，类别标题标“不重复计数”；没有并入呼吸道的（如原因未明的一次发热）作为独立病程。
- **未归入病程但已确认是孩子的记录**：在时间轴上用虚线圈独立呈现，并在本部分末尾说明数量和位置，不硬并进病程。
- **身份不确定**的资料不进入任何病程（见 2.1）。
- 资料不足时只保留已记录的经过，不做分析；分析过期时顶部提示基于哪天之前的资料、已过几天。
- 底部固定声明：辅助整理，不是诊断，不能代替医生。

### 2.3 后续措施

把所有后续事项集中，先“立即处理”，再按类别：

- **立即就医信号**（置顶）：与个体记录无关的通用危险信号，可展开依据，不因资料缺失而放松。
- **观察与护理 / 就医安排 / 向医生问清楚**：每项都标明**对应病程**（可点回）、**依据**（可展开）。
- **建议 与 已确认安排 严格区分**：建议标“建议”（虚线标签）；已确认安排标“已确认安排 · 日期”，只来自家长写下的预约或医嘱中的明确日期，显示日期和检查准备。建议不会自动变成预约，页面明写这一点。
- 医生沟通类问题写出出处（来自处方、家长提到等）；涉及口服药的问题提示“处方不等于实际服用”。
- 不从历史处方生成吃药提醒。
- 资料不足时只保留通用措施；分析过期时提示基于哪天、先看现在的情况或问医生。

## 3. “记一笔”与 HEALTH-03

“记一笔”在健康页首屏。它打开 HEALTH-03 已验收的独立工作区（爸妈手记 / 就医 / 已记录），不重做表单。工作区全屏打开，自带三标签并盖住站点菜单，因此任何时刻底部只有一排菜单；关闭回到健康页。HEALTH-03 保存并更正后的有效内容就是本页“家长记录 / 医院资料”的来源之一，撤销的不再出现。更正仍在“已记录”里进行，健康页本身只读。

## 4. 正式实施依赖（需确认后另发实施卡）

1. **读取访问保护**：页面、API、原图、缓存都要受保护（HEALTH-03 只覆盖写入侧独立会话）。需确定健康页读取是否与“记一笔”共用 `hr_session`，以及与站点现有访问方式的关系。
2. **事件与区间的数据**：时间轴需要“事件（类型、时间精度、来源层级、原件定位）”和“记录本身写明的区间（有症状 / 明确无症状 / 起止不明）”。区间只能来自记录明说的持续时间，不能由节点插值；当前 HEALTH-01/02 底账是否有足够字段，需实施前核对。
3. **病程归属**：病程与类别（呼吸道、发热、烫伤等）来自 HEALTH-02 的病程候选和更正留痕；“关联入口不重复计数”“未归入病程”“身份不确定”三种状态需由数据层明确给出。历史医院规范事实和历史原件尚未完整接通（HEALTH-03 验收已声明）。
4. **分析与措施的来源**：需要 HEALTH-M01 的已审核结构（结论、依据、医学证据、生成时间、适用条件、失效规则）；页面只展示已审核内容，不在页面里调用模型。过期天数阈值待定。
5. **预约数据**：“已确认安排”和首页健康提醒需要结构化的预约/复查日期入口（可由“记一笔”新增或从就医材料中的明确复诊日期提取，实施前定其一）。
6. **首页与站点菜单**：主菜单由三项改四项；提醒区加“生活 / 健康”标记，涉及现有提醒组件和底部导航留白。
7. **真实环境验证**：真实手机与读屏、深色模式、代理/HTTPS、多进程、真实数据库仍是上线前门槛。

## 5. 原型检查与限制

只做了手机主流程（390×844，含触摸滑动）和桌面（1280×800）溢出检查，37/37 项通过，覆盖：单排四项菜单；健康提醒红色十字图标与“健康”文字；三个部分且旧组织已删除；时间轴滑动、范围切换、节点选中、来源展开、原图入口；色带只来自写明区间、无患病天数或比例；虚线圈与身份未确认分开；分类展开、四块内容、处方与实际用药分开、发热不重复计数；后续措施排序、建议与已确认安排区分、无吃药提醒；资料不足与过期三处表达；“记一笔”三入口与关闭；手机与桌面无横向溢出、无脚本错误、无外网请求。关键截图在 `health-04-design-r1\screens\`。未跑全仓测试和生产构建。

**未验证**：真实手机与读屏、深色模式；示例中的医学内容、指南来源和照片均为合成占位，只演示结构；节点很多（数十条）时的分组与密度，只用 17 条示例验证过；红色十字在现有站点配色下的最终观感需在真实首页确认。
