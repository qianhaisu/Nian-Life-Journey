## 1. 风格与导航

- 温暖、清晰、手机易读。柔和的暖纸底色，圆润的大圆角卡片，彩色实心图标（彩色圆底 + 白色图形，带轻微立体感），装饰适量，不因此增加文字、卡片或操作层级。
- 类别与事件各有固定颜色和图标：呼吸道（蓝，肺）、发热（橙，体温计）、烫伤（珊瑚红，火焰）；事件：症状（粉，水滴）、体温（橙）、就医（青绿，十字）、检查（紫，烧瓶）、好转（绿，嫩芽）；附件用紫色回形针。
- 主菜单固定 **首页 / 记忆 / 健康 / 妈妈月报**，手机只有一排底部菜单，桌面为顶部菜单。
- 首页保留主照片、题签和“近期提醒”。健康提醒用**圆润红色十字 + “健康”文字**，普通提醒仍标“生活”。健康提醒只来自明确的预约或复查安排；点开落到健康页“后续措施”。不从历史处方生成用药提醒。

## 2. 健康页

顶部是标题和“记一笔”，下面一条三段跳转栏：健康时间轴 / 病程分析 / 后续措施。

### 2.1 健康时间轴

高保真参考“月份刻度、圆润连续色带、彩色事件图标、上下错开的日期与简短标注”，不采用参考图中的日期、医学结论、天数或比例。

- **全程概览**（顶部，紧凑）：完整资料跨度一屏看全，含月份刻度、圆润色带和全部事件小点，并用方框标出详细时间轴当前看到的位置。点击或拖动概览，详细时间轴同步移动；手指滑动详细时间轴，概览方框同步移动；点小点可直接选中事件。
- **详细时间轴**（概览下方）：
  - 月份刻度 + 圆润连续色带；事件图标带日期和简短标注，上下两排错开，用柔和曲线连回色带上的真实日期点，标注互不重叠。
  - 手机左右滑动（不是缩小桌面大图），默认停在最近，首屏可同时看到概览和多个事件；有 全部 / 近3个月 / 近1个月 三档范围和左右箭头。桌面同样横向滚动。
  - 点击图标，下方显示详情：日期、内容、来源类型（家长记录 / 医院资料 / 汇总转述）、来源出处、所属病程链接；医院资料带附件入口；只写了起点的记录说明“结束不明”。
- **色带三种状态 + 未知**：有症状记录（暖珊瑚）、明确无症状记录（薄荷绿）、起止不明（虚线）；其余为斜线底色“资料未知（不代表健康）”。
  - 色带只来自记录本身写明的持续时间（例如“这三天一直在咳”）。零散节点不连成区间，无记录的时间不当作健康期，也不推算持续有症状。
  - 没有可靠区间依据时不显示患病天数或比例。
- 已确认是张年、尚未归入病程的节点用虚线圈；身份不确定的资料放在时间轴下方的折叠项，明确不在时间轴上、不用于分析。
- 资料不足时时间轴只显示已有记录并如实缩短覆盖范围；分析过期时提示“最近一条是 X 日，之后已 N 天没有新记录”。

### 2.2 病程分析

类别（呼吸道、发热、烫伤）和具体病程两级**默认都折叠**。类别行是彩色图标 + 短名 + 次数；病程行是标题 + **日期范围**（结束未知写“未知”）。展开具体病程后**只有三部分**：

1. **发展经过**：按日期的关键变化。明确结束的病程带“结束 X 月 X 日”；结束未知就显示“结束：时间未知”，不因记录中断推断恢复。
2. **病程总结**：一两句自然的话概括发展与判断；重要的不确定性直接融入这句话（例如“之后体温和精神没有记录，还不能说已经好了”）。页面不设“查看依据”入口，底层来源、版本与审核信息在数据层保留。
3. **就医记录**：逐次显示时间、医院、科室、处方、报告。
   - **处方**分两行：“医院开的”（医院资料）与“家长确认用了”（家长记录，没有记录就写“暂无记录”）。处方不等于已使用。
   - **报告**是紫色回形针附件按钮，点击打开对应附件页；病程里不铺图片。
   - 没有就医的病程写“这次没有就医记录”。

规则：发热类别里，关联到呼吸道病程的体温记录只作关联入口，明写“不重复计数”；同类不同次病程分开；资料不足时只保留经过和就医记录，不做总结；分析过期时顶部提示已过几天。

### 2.3 后续措施

只有两类，每项简短，标明对应病程（可点回），页面上没有“依据”入口：

- **观察与护理**：如早晚量体温、夜间垫高上半身、看烫伤处（并写明最近记录日期）。
- **就医安排**：
  - 已确认预约：只来自家长写下的预约或医嘱中的明确日期，带日期时间和检查准备，标“已确认预约”。
  - 建议（虚线标签“建议 · 尚未预约”）：不显示成预约，不自动变成预约。
  - 条件性就医建议（如呼吸费力、嘴唇发青，请立即就医）放在此类首位，标“建议 · 遇到才需要”，与已确认预约区分。
- 资料不足时只保留通用措施；分析过期时提示基于哪天。底部一句：辅助整理，不是诊断，不能代替医生。

## 3. “记一笔”与 HEALTH-03

“记一笔”在健康页首屏。它打开 HEALTH-03 已验收的独立工作区（爸妈手记 / 就医 / 已记录），不重做表单；工作区全屏、自带三标签并盖住站点菜单，任何时刻底部只有一排；关闭回到健康页。HEALTH-03 保存并更正后的有效内容是本页“家长记录 / 医院资料”的来源之一，撤销的不再出现；健康页本身只读。

## 4. 医学文案与数据边界

原型保留有代表性的具体文案，但这只是展示，**不等于完成医学审核**：正式接入前必须核对来源与适用条件，不能把原型里的示例阈值（如体温、天数）当作固定医学规则。页面隐藏“依据”按钮，但底层的来源、版本、审核信息、生成时间和适用条件必须保留，可追溯到家长记录 / 医院资料 / 汇总转述 / 医学证据。

## 5. 正式实施依赖（确认后另发实施卡）

1. **读取访问保护**：页面、API、原图/附件、缓存都要受保护；需确定与 HEALTH-03 `hr_session` 的关系。
2. **事件与区间数据**：事件（类型、时间精度、来源层级、原件定位）和“记录本身写明的区间”（有症状 / 明确无症状 / 起止不明）；区间不能由节点插值。需核对 HEALTH-01/02 底账字段是否足够。
3. **病程、类别与就医记录**：病程与类别、日期范围（含结束已知/未知）、每次就医的医院/科室/处方/报告附件，以及“实际使用”的家长确认，均需由数据层明确给出；发热与呼吸道的关联、未归入病程、身份不确定三种状态同样。历史医院规范事实和历史原件尚未完整接通（HEALTH-03 验收已声明）。
4. **总结与措施的来源**：需要 HEALTH-M01 的已审核结构（结论、来源、版本、审核状态、生成时间、适用条件、失效规则）；页面只展示已审核内容，不在页面里调用模型。过期阈值待定。
5. **预约数据**：“已确认预约”和首页健康提醒需要结构化的预约/复查日期入口。
6. **站点改动**：主菜单三项改四项；提醒区加“生活 / 健康”标记；概览与详细时间轴的联动交互需要真实设备验证。
7. **上线前**：真实手机与读屏、深色模式、代理/HTTPS、多进程、真实数据库。
