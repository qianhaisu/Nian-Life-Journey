## 2. 推荐方案

**一个入口，四个底部标签（记录 / 用药 / 加资料 / 已记录），一句话起步。** 不改首页，不做总览（HEALTH-04）。原则：不强迫填完、没填≠正常、**发生时间与记录时间分开且各种含义不混**、不猜、不换算、不自动归属、不新增医学结论、不冒充今天状态、待核不会自动变已确认。

对原 8 个问题的处理已收成推荐方案（不再让 Teddy 选技术参数）：

| 项 | 推荐 |
|---|---|
| 入口 | 独立健康录入入口，首页不加催促（无红点、无计数） |
| 新建病程 | 本批不开放家长新建；只能选已有病程或「暂不确定」 |
| OCR | 另行批准，本批只做上传/手填待核 |
| 纠错原因 | 现有五项可用（写错了 / 后来想起更准确的 / 看清了原件 / 记到别的孩子·别的事上了 / 其他） |

## 3. 四条流程（输入 → 确认 → 保存反馈 → 查看/更正）

### 3.1 记今天 / 补历史
1. 写一句话（空则提示）。
2. 发生时间**四选一，含义互不混淆**：**刚刚**（发生时间 = 你点“刚刚”的那一刻，精确到分钟；保存失败重试也不变）；**今天（时间不详）**（记为今天这一天，不记成现在这一分钟）；**其他日期 / 时间**（日期不得晚于今天；再选「能到几点几分 / 只知道是哪天 / 大概那几天」，选分钟必须填几点）；**不确定**（发生时间留空，不猜）。记录时间永远是保存那一刻，自动。预览分行显示。
3. 可选补充：体温（℃ 30–45 / ℉ 86–113 各按各的范围）+ 量法；精神/吃/睡/饮水/尿量选项，每项有「没留意」。
4. 保存 → 已保存 + 查看/更正/再记一条。**保存失败**：内容保留、一键重试。
5. **防重**：每次新录入有一个**提交 ID**，失败重试沿用同一 ID（只保存一条）；同一次提交被再次提交 → 「已经保存过了」；点「再记一条」是新 ID，**内容相同也会保存**（不按内容吞新事件）。
6. **存储失败说实话**：浏览器存不了时，不再提示「已保存」，改为「只暂时保留在这个页面，还没有持久保存」，页头持续警示，记录带「仅临时保留」标签。

### 3.2 实际用药
- 四类：处方 / 打算用 / 已经用了 / 没用·停用；**每一类都有发生时间入口**（处方默认「今天（时间不详）」，可改成昨天的日期；已经用了默认「刚刚」）。补录昨天的处方不会变成今天。
- 「没用·停用」共享入口，保存时区分三种：**没给**（该用没用）/ **停用**（不再用）/ **给了但吐出来了**（记成“已经用了 + 吐出，吸收多少未知”，明确**不等同没给**）。
- 写了数量必须有单位；选「其他」必须写具体单位；量/次数可选「不知道」；数量 >0、次数 ≥1；不做换算。处方不代表已吃，疗程默认未知。

### 3.3 加资料（按类型确认）
- 四个模拟示例：处方单、**本人检验单（没有药物字段）**、**剂量数字清楚而单位看不清**、别人的化验单；另有粘贴文字入口（演示里套用示例）。
- 字段随类型变化：处方 = 患者/日期/诊断原文/药名/规格/剂量/单位；检验单 = 患者/日期/原文/检验项目/结果/单位/参考范围，**不显示也不要求药物字段**。诊断为原文块，不改写。
- 「确认并保存」只要求**该类型**的必填项 + 「是张年」；按钮下方直接写「还需要：……」。
- **剂量数字看得清、单位不清**：数字原样保留，明示「单位没确认前，它不会被当作可用剂量」，可「先存为待核」，不要求抹掉数字；未确认数值不写成结构化剂量。
- 别人的资料：明确「不会放进张年的记录」，只能放弃。
- **待核只有明确确认才变已确认**：详情里列出「还差什么」，需点「确认是张年」+「核对无误，标为已确认」；**更正其他字段不会自动升级**。

### 3.4 纠错、撤销归属、关联、来源确认
- **纠正覆盖录入的核心信息**：观察 = 内容、发生时间（保留分钟/日期/近似精度）、体温+单位+量法、精神/吃/睡/饮水/尿量；药物 = 药名、类别（含没给/停用/吐出）、发生时间、次数、单次量、单位（含具体单位）；资料 = 是不是张年、按类型的全部字段。校验与录入一致（含℉）。原因必选；无改动/无原因挡住；前值留在历史。
- **记错孩子**：「这不是张年的」→ 必选原因 → **撤销有效归属**（从主列表移到折叠的“已撤销归属”，不进病程），**历史保留，可恢复**。
- **多人冲突（表述已收窄）**：他人刚改过同一条时，界面明确写：**你的改动还没有保存**；**当前值**（已保存的，对方的）；**你的草稿（未提交）**（可复制）。两个选择及后果：**用我的，再更正一次** → 新增一次更正，历史依次是「原值 → 对方的 → 你的」，当前值变成你的；**保留对方的（丢弃我的草稿）** → 你这次草稿不保存。只有已保存的更正才进入历史。
- **病程关联**：明确属于 / 可能相关（不计入）/ 暂不确定（默认）；不按日期自动归属。
- **来源待确认（让家长看见依据）**：并排显示**两份可读的合成原件**（日期、内容、**变化处高亮**），选出「依据第几版」+ 必填理由 → 确认；拿不准可「稍后再说」，保持待确认；没选版本不能确认。历史记下谁/何时/为什么/第几版→第几版。**不要求仅凭版本号确认**。
- 空状态：「还没有记录」+ 去记录。

## 6. 正式实施缺什么（HEALTH-02 没有、需要新做）

1. **写入服务**：现只有文件账本 + CLI。需要服务端入口包装 `planImport→apply`、`applyCorrection`、`confirm-binding`，用 `entryId` 幂等；返回人话化结果。
2. **并发更正的过期检测（本轮只修设计映射，不改 HEALTH-02 代码）**：`Correction.baseVersion` 只记录实体**版本**，而**事实版本不会随每次更正增加**，所以仅加一个 `expectedVersion` 字段**不能**防住两个并发更正。正式需要一个**每实体修订号（revision/etag）**，任何更正、链接更正、撤销归属、确认都使其递增，并在**写事务内**比较「期望修订号 = 当前修订号」；不一致 → 拒绝并返回对方的更正（即 3.4 的冲突界面）。文件账本的锁只能保证串行，不能替代这个检查。上线前须为「两个并发更正同一字段/不同字段」补测试。
3. **读取投影**：不能每次请求载入整账本（参见 CLAUDE.md 渲染路径规则与 `getStore()` 教训）；需要按病程/记录的读取接口或缓存。
4. **存储与并发**：文件账本是单机单写者；上线前须决定单机单写服务 + 文件锁，或先完成真实 Postgres 事务/并发验证再接数据库。**本轮不安装 PostgreSQL、不接 RDS**；未经另行设计与验证，文件方案不直接上线。
5. **访问控制（正式实施必备）**：页面、API、原件（图片/PDF）**都需要服务端授权**。隐藏路径、未认证的「我是妈妈/爸爸」选择器都**不能**当权限，也不是可靠的作者来源。私有链接、共享口令、IP 白名单**不是**未经评估就等价的选项：实施卡需依据项目现状（当前不做登录、单用户个人项目、生产在 ECS 私有站/公开站分离）给出可执行方案，并写明作者字段的可信来源（例如与凭据绑定的身份），再实现。
6. **图片上传**：走既有媒体策略（对象存储、SHA-256 身份，不用临时外链）；本批不接 OCR/模型；若之后自动出草稿，须另行批准并遵守既有识图约定。
7. **新词表与字段**：`parent_observation`、`parent_entry_now/parent_stated`、`family_document`、`attributes`、`medication_stopped`、`outcome:"vomited"`、撤销归属机制；需在类型/校验/时间轴登记并补测试。
8. **病程来源**：下拉的病程来自账本 `episode`；家长不能新建。
9. **离线/弱网**：失败重试已有；正式版建议本地暂存未提交草稿，提交带同一 `entryId`；存储失败要如实提示（原型 3.1-6）。
10. **无障碍与视觉**：触控区 ≥44px、错误 `role=alert`、`prefers-reduced-motion`；沿用现有配色，不改首页。

## 7. 与产品原则的对照
- **原则四（隐形自动化）**：这是家长「录入」工具，不放在家人阅读站首页；不加红点/计数，待确认只用安静的一行（「有 N 条可以顺手确认，不急，也没有提醒」）。
- **原则二（两个时钟）**：每条同时显示「记录于 / 发生于（含精度与含义）」；未知明说。
- **原则八（可追溯）**：修改历史、来源版本对照、撤销归属都保留。
- 不新增医学结论；处方≠已服用，疗程默认未知；吐出≠没给。
