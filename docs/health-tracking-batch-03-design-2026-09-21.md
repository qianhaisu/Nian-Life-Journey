## 2. 推荐方案（一个，不做对比）

**一个入口，四个底部标签，一句话起步。** 不改首页，不做总览（HEALTH-04）。

| 标签 | 做什么 | 设计要点 |
|---|---|---|
| 记录 | 记今天 / 补历史 | 只有「一句话」必填；时间三选一（刚刚·今天 / 某个历史日期 / 不确定）；体温、量法、精神、吃、睡、饮水、尿量收进「再补充一点（可选）」，用选项而非问卷；每项都有「没留意」 |
| 用药 | 实际用药 | 先选四种之一：**医生开的处方 / 打算用 / 已经用了 / 没用·停用**；药名 + 次数 + 单次量 + 单位，均可选「不知道」 |
| 加资料 | 文字/图片 → 待核草稿 | 草稿突出患者、时间、诊断原文、药名/规格/剂量/单位，右侧原件示意与字段联动高亮；看不清就先存待核 |
| 已记录 | 查看、纠错、关联、来源确认 | 卡片带状态标签；点开看修改历史、纠正、设置病程关联、确认来源版本 |

原则：**不强迫填完、没填≠正常、发生时间与记录时间分开、不猜、不换算、不自动归属、不新增医学结论、不冒充今天状态**（已记录页顶部写明「没有记录的日子不代表没事」，并只显示「最近一次观察记录」的时间）。

## 3. 四条流程（输入 → 确认 → 保存反馈 → 查看/更正）

### 3.1 记今天 / 补历史
1. 写一句话（空则提示「先写一句话再保存」）。
2. 选时间：**刚刚**（记录=发生=现在）；**历史日期**（日期不得晚于今天；再选「能到几点几分 / 只知道是哪天 / 大概那几天」）；**不确定**（明确写着「发生时间留空，不猜」）。记录时间永远是现在（自动），预览里分行显示。
3. 可选补充：体温（30–45℃ / 86–113℉ 范围校验）+ 量法；精神/吃/睡/饮水/尿量选项。
4. 保存 → 「已保存」+ 「查看/更正」「再记一条」。**保存失败**：红色提示、内容保留、一键重试。**重复提交**：90 秒内同内容 → 「这条刚刚已经保存过了，没有重复保存」。

### 3.2 实际用药
- 四种类型各带一行人话说明；处方记录始终标注「不代表已经吃了 / 疗程：未知」，**不会自动标成服完**。
- 写了数量必须选单位（否则「写了数量就要选单位」），选了单位必须有数量；「量不知道」「次数不知道」是明确选项；数量 >0、次数 ≥1。**不做剂量换算**，只记看到的数字和单位。
- 没用/停用可写原因（没吃、吐了、医生让停、孩子不肯…）。

### 3.3 加资料
- 三个示例：清楚的处方单（个别项待核）、不太清楚的照片（多项看不清）、别人的化验单（姓名对不上）；另有「粘贴文字」入口（演示里套用示例草稿）。
- 每个字段有状态「清楚 / 待核对 / 看不清」；诊断为原文块，标「原文，不改写不总结」。
- 「确认并保存」需要：选「是张年」+ 日期、药名、剂量、单位都有；不满足只能「先存为待核」。写了剂量没单位拒绝。别人的资料：明确提示「不会放进张年的记录」，只有「放弃」。

### 3.4 纠错与关联
- 点任意记录 → 详情：状态标签、关联病程、修改历史。
- **纠正**：预填当前值 → 改动预览（前值 → 后值）→ **原因必选** → 保存；无改动、无原因、数字/单位不合规都会挡住；前值永远留在历史里。
- **多人冲突**：他人刚改过同一条时，你的改动**不覆盖**，同时展示两边；「用我的，再更正一次」（对方那次仍在历史里）或「保留对方的」。
- **病程关联**：明确属于 / 可能相关（不计入）/ 暂不确定（默认）；文案写明「不会按日期自动归属」。
- **来源待确认**：例如「资料改过，但没说明依据原件哪一版」——列出旧依据，选版本 + 必填「你怎么知道的」→ 确认；历史记下谁、何时、为什么、第几版→第几版；重复确认提示「已经确认过了，没有重复记录」。**不需要改资料内容**。
- 空状态：「还没有记录」+ 去记录；历史上的事也可补。

## 5. 界面动作 → HEALTH-02 字段映射（精简）

复用既有模型，不另造底账。核对依据：`v2/lib/health/{model,ledger,graph,timeline}.ts` 与 `test/health-*.test.mjs`。

| 界面动作 | HEALTH-02 落点 |
|---|---|
| 记今天/补历史 | `observation`：`role:"parent_observation"`、`recordedAt`=现在、`occurredAt`/`occurredPrecision`（分钟/日/近似）、`timeBasis`（`parent_entry_now` / `parent_stated` / `unknown`）、`text`；**不确定 → `occurredAt:null` + `timeBasis:"unknown"`**（既有校验只在 `occurredAt` 有值时要求非未知依据，兼容）。体温 → `measure{value,unit,method}`（值+单位校验已存在）；精神/吃睡等 → `attributes`（未填=不写字段；「没留意」=`unnoticed`）。来源：新建 `source{layer:"parent_entry", 录入人, clientId}` + `from_source` 链接 |
| 实际用药 | `observation.role`：处方→`prescription`、打算→`plan`、已用→`medication_administered`、没用→`medication_not_given`（时间轴分类已支持）；`dose{value,unit}` 缺单位由 `quantityProblem` 拒绝；未知量/次数=不写字段；`treatmentCourse` 保持 `unknown`；不写任何病程结束 |
| 加资料 | `source{layer:"family_document", sha256, relPath}` + `canonical_fact` 草稿（`reviewStatus:"draft"`→确认后 `parent_confirmed`）；`structured{name,spec,dose,…}` 走既有校验；患者不符不建 `of_encounter`/不归入张年；原文进 `value` 原样保存 |
| 纠正 | `applyCorrection{type:"field", changes[], author, at, reason}`：前值自动记入 `before`；同 id 同请求幂等；改后有效内容重验（日期/单位/精度） |
| 关联病程 | 明确→`attached`，可能→`candidate`（不计入），暂不确定→不建链接；后改用链接更正（`afterRole`）；不按日期归属（HEALTH-02 本来就不这么做） |
| 来源待确认 | 已有 `bindingEvents`（pending）与 `links + toVersion + confirmation{by,reason}`；界面「确认」= CLI `confirm-binding` 的同一批次；重复幂等、不同版本冲突不覆盖 |
| 重复提交 | 客户端生成 `clientEntryId` 作为强身份（如 `obs:<id>`）→ `planImport` 判 duplicate |
| 保存失败/重试 | `applyPlan` 拒绝整批零写入；重试同一 id 幂等 |

## 6. 正式实施缺什么（HEALTH-02 没有、需要新做）

1. **写入服务**：现只有文件账本 + CLI。需要服务端入口（server action / route）包装 `planImport→apply`、`applyCorrection`、`confirm-binding`，带 `clientEntryId` 幂等键；返回人话化的结果（新增/重复/冲突/待确认）。
2. **过期检测**：`Correction.baseVersion` 已记录，但 `applyCorrection` 不拒绝过期基线。多人冲突（3.4）要加 `expectedVersion`：当前版本≠期望 → 返回「对方的更正」而不是覆盖。这是本设计唯一需要动 HEALTH-02 核心的点，规模小。
3. **读取投影**：时间轴/详情不能每次请求都载入整账本（参见 CLAUDE.md 渲染路径规则与 `getStore()` 教训）；需要按病程/按记录的读取接口或缓存投影。
4. **存储与并发**：文件账本是单机单写者；上线前须决定（a）单机单写服务 + 文件锁，或（b）等数据库接入并**先做真实 Postgres 事务/并发验证**（仍是接入前必验项，本轮不做）。
5. **权限与身份**：项目当前不做登录；原型里「我是 妈妈/爸爸/奶奶」是**未认证**选择器。正式版至少要一个写入准入（私有链接/共享口令/IP 白名单三选一）和录入人字段来源。健康数据只走私有可见性。
6. **图片上传**：走既有媒体策略（对象存储、SHA-256 身份，不用临时外链）；本批**不接 OCR/模型**——若之后要自动出草稿，须另行批准，且遵守「识图用 DeepSeek flash、不用 Claude 批量识图」的既有约定。
7. **新词表**：`parent_observation`、`parent_entry_now/parent_stated`、`family_document`、`attributes` 需要在类型/校验/时间轴里登记；`parent_observation` 与既有 `fact_kind` 映射的角色分类需补测试。
8. **病程来源**：下拉的病程来自账本 `episode`；家长**不能新建病程**（见待决 3）。
9. **离线/弱网**：手机保存失败已有重试；正式版建议本地暂存未提交草稿（localStorage），提交时带同一 `clientEntryId`。
10. **无障碍与视觉**：触控区 ≥44px、标签与错误 `role=alert`、`prefers-reduced-motion`；沿用现有纸底/鼠尾草/陶土配色，不改首页。

## 7. 与产品原则的对照（防偏）
- **原则四（隐形自动化）**：这是家长「录入」工具，不放在家人阅读站首页，也**不加红点/计数催促**（原型里待确认只用安静的一行提示「有 N 条可以顺手确认，不急」，已去掉底部标签红点）。「加资料」不做首页主按钮。
- **原则二（两个时钟）**：每条同时显示「记录于 / 发生于（含精度）」；未知明说，不给出裸时间。
- **原则八（可追溯）**：修改历史、来源版本、原件对照都可点开。
- 不新增医学结论，不做诊断/建议；处方≠已服用，疗程默认未知。
