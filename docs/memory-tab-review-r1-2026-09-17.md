## 3. 必须修正的样稿问题

### A. 月总结不是改成两个段落就完成了

`mockup-r1.html:55–56` 仍保留上一轮点名的绝对化、偏好、地点和模仿机制补写。R1 报告 B 节一边说明来源未核实，一边继续把这些表达放在阅读正文；“生产已经发布”不等于这些新增表达已经有证据。

R2 应直接删改正文，围绕最多两个有证据的变化写总结，不只在报告标注“建议修改”。如果只确认一个主题，就写一个主题，不为凑两段添加生活习惯判断。已有样稿中的“来串门”“想摸”“吃着吃着”“咳嗽了几声”等地点、意图、过程和次数，也按同一标准核对。

### B. “家庭”是现状兜底，不是发言人需求的完成标准

`contributors` 为空，只能证明当前这条展示路径拿不到显示名，不能证明原始资料没有姓名。代码提供可核对的路径：

- `v2/lib/ingest/wechat-markdown.ts` 从消息头解析 sender，输出 `senderName` 和来源定位。
- `v2/lib/ingest/wechat-weflow-json.ts` 读取 `senderDisplayName` / `senderUsername`。
- `v2/lib/ingest/wechat-import.ts` 保留 `providerExternalId`、`senderDigest`、`documentDigest`、`recordOrdinal`、`importBatchId`。
- `v2/lib/ingest/wechat-content-dedupe.ts` 有发送者摘要复算逻辑。

先在本机的对应原始导出/批次产物中，用会话、原始消息定位、时间、发送者摘要、正文和附件证据交叉核对。不要跨全盘搜姓名，也不要靠猜测反推哈希。可恢复的显示真实名字；角色单独核验。确实无法恢复时，使用稳定且可区分的“发言人 A（姓名待核实）”等临时标签，不能把所有人合成同一个“家庭”。

9/1 的“回复某个班级账号的图片”不足以证明发送者一定是家长：也可能是其他老师，甚至要先排除自回复。准确结论应为“现有老师归属待核实”，不能用另一条未经证实的身份断言替换它。样稿允许把未核实角色改为中性表述；保留生产不动不等于本机设计稿必须复刻疑似错误。

### C. 21 张候选、7 张样图、最终精选是三个不同数量

交付聊天摘要称 9/1 展示全部 21 张；R1 报告 D2 与 `event-sample-sep01.html:34–48` 实际为 7 张图片及其余候选的 ID 清单。这不能算完整图片呈现。

用户要的是“先去重，再将最终精选全部展开”，不是把 21 张候选全部变成相册。R2 对该样本做必要的局部精选：本地精确去重/分组，DeepSeek v4.1 Flash 比较场景动作，形成候选 → 排除/保留 → 最终 N 张的清单；Event 默认实际显示全部 N 张。N 可少于 21，不为补数量保留同质照片，不用 ID 清单代替图片。

### D. 月页原位展开仍没做

`mockup-r1.html` 没有 `<details>` 或等价的原位展开实现，9/1 和 9/8 仍跳到 Event。R1 演示的是 Event 的资料/ID 清单展开，不能替代“月页展开当天精选”。

R2 至少一个有剩余精选图的日期必须在原位置展开/收起，不跳页面，不增加“去相册”的第二入口。月页仅一套日照片区；Event 展示最终精选全集。无剩余图时不显示空展开按钮。

### E. 响应式裁切、标题和纯阅读效果未验收

- 报告称手机 `50% 19%`、桌面 `50% 45%`，但 `mockup-r1.html:31` 是固定内联 `50% 45%`，19% 只出现在说明文字。关联 CSS 没有为这张图实现该手机覆盖规则。
- 报告明确承认真实视口约 501px，未获得桌面宽度。Sharp 裁切模拟不能替代桌面整页及手机断点验收。
- 三份 Event HTML 缺少正文区可见的故事主标题（浏览器 `<title>` 不算），无法验收用户要求的标题换行效果。
- 样稿中仍将媒体 ID、审核状态、代码字段和修订说明穿插在卡片与正文之间；9/8 还把前后对照放在故事之前。应把这些移出产品阅读页，单独放报告/核对页。

R2 交真实 390px 与 1280px 等代表性视口的封面/月页/Event 截图及实际 `innerWidth`；工具做不到的维度应保留未验证，不能宣称数学模拟已完成整页验收。

### F. 来源去重还需保留证据

9/8 样稿说明同时出现“20 个 ID 有大量重叠”和“唯一 ID 仍为 20”，自相矛盾。内容相同、时间相同不足以认定是重复捕获；还需核对会话、发送者与附件/引用关系。确认重复后可合并展示，但要保留合并前后来源 ID 映射及完整原文，不凭正文相同把不同人说的话合并。

## 4. 诊断报告需要收窄的结论

1. **补真正的稳定来源链。** R1 第 5 节给了 media ID，但 `raw_source` 仍写两个会话“或”，不是唯一 source ID。补 `media.raw_source_id`、asset ID、唯一消息定位、最新审核和事件关联检查；跨会话重复单列，不能把会话 ID 当 source ID。附本机只读探针/脱敏结果路径。说明 R0 的 64 与 R1 的 12 分别统计了什么，并补各层可交付/排除数量；12 个候选只有部分达到尺寸门槛，不能称“全部尺寸合格”。
2. **归档存在不等于故事更新恢复。** 分别报告最新导入来源、照片完整层、默认时间线、已发布故事和月总结的截止日期。照片到了 9/16，不能据此撤销故事停在 9/14 或下游整理未持续运行的问题；后两项仍需原证据/现状核对。
3. **来源门槛不等于截图检测。** 9/6 两张截图因为不满足来源/主体门槛暂未展示，并不能证明系统具备截图识别能力。截图来自可信来源时仍需相同内容筛选；保留 MEMORY-03 的截图排除任务。
4. **不能只凭队列表重建完整执行史。** 13 行、同日 succeeded 能说明现存队列记录；不能证明 Organizer 历史上只执行过一次，更不能排除其他入口。保留“当前表中记录”的表述。
5. **时间字段要对照写入代码。** `media.taken_at` 是无时区挂钟字段；当前 WeChat 导入器由 `wallClockOf(message.sentAt)` 写入，不宜笼统称其一定是原始拍摄时间，也不能未经追踪把旧日期差异解释成隔天发照片。按实际来源和代码说明。
