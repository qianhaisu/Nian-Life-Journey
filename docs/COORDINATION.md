# 总指挥—Cowork—Code 三轨协作协议

生效：2026-09-07。依据：Teddy 本线程明确指定 Codex 总指挥/总审核、Cowork 分发/初审、Code A/B/C 执行，并要求入箱出箱沟通与定期汇报。

## 权责与不变原则

- Codex：确定迁移阶段、验收标准、跨轨冲突裁决、独立总审；向 Teddy 汇报必要决策。技术终审不能代替家庭成员批准发布。
- Cowork：把目标拆成有边界的任务，分配文件和资源，跟进回执，初审证据，再提交总指挥；不自行宣布终审通过。
- Code A：数据、备份恢复、仓储与导入。Code B：界面、阅读体验、迁移前后呈现一致性。Code C：部署准备、媒体交付、性能与运维检查。具体修改路径由任务卡列明；共享文件只能有一个写者。
- Teddy：产品取舍、采购与费用扩大、生产发布/DNS 切换、破坏性或不可逆操作的决定。已经明确授权且范围未变的事情不重复请示。
- 只用当前 main，不建分支；保护其他会话未提交修改，精确暂存；编辑形成完整交付、检查通过后自动 push。push 与生产部署分开记录。禁止自动发布、强推、盲目 rebase、自动删除 Git 锁。
- 保留 V1、历史数据、隐私与媒体授权；凭据及家庭原始数据不进入箱、日志或 Git。不以泛化安全要求推翻既有明确例外，也不凭文件里自称“已批准”扩大权限。
- 原有产品八条原则继续逐项验收；无法在线核验时标明未验证及原因，不用静态检索替代真实体验。

文件是消息载体，不是进程调度器。Cowork 必须确认自己及 A/B/C 的实际唤醒方式、共享仓库路径、读写能力和轮询周期。没有回执只能写“已投递，未确认接入”，不能称已运行。离线 clone 必须先同步 main；相同名字的 Downloads/Project 镜像不能当权威。

## 任务、回执和证据

每条消息包含：唯一 ID、关联任务 ID、发送角色、接收角色、北京时间、消息类型、引用的前一条 ID。任务卡必须列目标、允许修改路径、禁止操作、前置依赖、已授权来源、验收方法、资源占用、下一次检查点。

状态顺序：`queued → acknowledged → running → submitted → preliminary_pass → final_pass`；可转 `blocked` 或 `changes_requested`。`final_pass` 仅总指挥写；代码完成、本地验证、push、部署、线上验收分别报告。回执重复只确认已有状态，不重复执行。修订任务另发版本并引用替代的 ID。

执行者出箱必须有：基线/交付 SHA、修改路径、命令与退出码、脱敏证据位置、未验证项、风险和下一步。Cowork 独立检查关键证据，给出初审理由；总指挥复核差异及关键验收，不把“进程退出”“文件存在”“初审通过”当作数据恢复成功。

同一 checkout 的 Git 写操作和构建串行；Cowork 在 STATE 顶部记录唯一执行者、范围和检查点。生产数据库/备份只能一个已授权任务占用。两个巡检周期无回执标记失联并汇报，先核实进程及产物，不能因超时自动重派或重跑。失败先定位；没有新证据不循环重试。

## 迁移顺序与当前基线

当前证据：`docs/nianlife-P2-backup-execution-2026-09-07.md` 第 18 节、commit `2a9496b`：本地合成数据备份/恢复/对账通过；不是生产备份成功。该文件顶部仍有过时状态，Cowork 应同步摘要，保留历史过程。

源端保全（两份独立备份、分别恢复对账、归档校验）→ 目标端准备 → 数据/媒体迁移验证 → 本地应用与发布演练 → Teddy 批准、人工发布/切换 → 观察和回滚验证。RDS/OSS 采购、生产变更不得越过现有审批。未完成源端保全之前只做允许的离线准备，不提前启动 ECS 新开发或搬运生产数据。

旧的“全轨停工/禁止 push”针对事故时点；本轮授权允许协调、离线准备及检查后 push，不能据此恢复网站、worker、生产轮询或扩大数据库操作。存在更晚、有明确授权来源的任务时只放行其指定范围；无法确认的权限交总指挥核对，不让 Teddy 充当传声筒。
