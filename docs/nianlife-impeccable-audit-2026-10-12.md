## 应保留的产品特色

首页让家人先遇见真实生活与一句近况，日页保留原话、日期、当时年龄和资料入口，具有明确的家庭档案气质。旅行地图和足迹、月报的成长分工都有自己的用途，不应为了统一样式改成同一种卡片。

已有 `lang`、skip link、可见焦点、导航当前态、明确图片 / 播放按钮、原生 select 和多处模态返回机制。首页回忆与照片查看器的背景隔离、Esc、历史返回和焦点归还已经实际通过，应成为其他弹层的共同标准。

## 优先改善的五个方面

### 操作层必须可退出且支持键盘

**I01，P1，生产复现：健康附件焦点进入背景。** 打开真实附件后，Tab 能越过弹层进入页面，Esc 关闭也没有将焦点归还附件链接。影响键盘与读屏用户的方向感和操作范围。位置：`v2/app/health/health-view.tsx:46`，与首页回忆 / 照片模态行为不同。采用现有成熟 Dialog 或原生 dialog，统一初始焦点、背景不可操作、焦点循环、Esc / 返回、触发处归还。标准与模式见 [WAI Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。建议 `/impeccable harden`。

**I05，P1，生产实现与交互确认：照片放大只有双击入口。** 双击可进入放大态，生产模态只提供关闭、上一张、下一张，没有放大 / 还原按钮；同版源码的键盘处理仅有 Esc 和左右键。放大功能缺少键盘等价路径，不能把“可以键盘打开照片”当作全部功能合格。位置：`v2/components/photo-viewer.tsx:94`、`:124`、`:136`。增加放大 / 还原按钮和状态说明，放大后保留可操作的移动和退出。建议 `/impeccable harden`、`/impeccable adapt`。

### 关键文字要可读且准确表达资料性质

**I02，P1，生产测量：功能小字对比不足。** 月报 11.5–11.84px 的绿字 / 浅绿底约 3.87:1，蓝绿图例 / 白底约 4.14 / 4.18:1；健康录入桌面提示与返回字约 4.42:1；inbox 空态字约 2.64:1。这些小字需要 4.5:1，不因加粗自动成为大字。位置：`v2/app/mom-reports.css:132`、`:151`、`:162`；`v2/app/health/record/record.css:34`；`v2/app/inbox/page.tsx:39`。保留面色与维度颜色，为功能字增加深色 token。参照 [WCAG Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。建议 `/impeccable colorize`、`/impeccable audit`。

**I03，P1，表达问题：健康累计指标把估算放进确定语气。** 指标标题写“累计生病”，疑似区间、结束不明、间隔补算等限定默认藏在说明按钮内。读者容易将结果当作确诊患病天数。位置：`v2/app/health/health-view.tsx:165`、`:213`。标题表达记录 / 估算性质，数字旁常驻一句简短限定；保留原记录和完整计算说明。这是资料表达改善，不新增医学判断。建议 `/impeccable clarify`。

**I08，P2，历史身份：月报仍使用“最近 / 当前”。** 目前可选月报为历史月份；封面“最近的张小年”与局部“当前”字样需依靠月份注释才能正确解释。首页近况也应让整理到的月份就地可见。将历史月报改成“这个月 / 当时”，限定放在相关段落开头。保留原始日期，不编造更新后的近况。建议 `/impeccable clarify`。

### 手机与大字模式不能依赖精细点按

**I06，P2，操作难度：健康短区间与说明按钮过小。** 生产短区间最小约 8×20px，说明按钮约 18.36×14.08px；圆点为 28×28px。横向时间轴在合成触摸中能滚动，但这不证明小目标容易点中。位置：`v2/app/health/health.css:57`、`:74`、`:80`。保持日期比例，扩展合理命中区，密集处提供分组与同等记录列表入口。44px 是本方案的主要操作目标；WCAG 2.2 AA 使用 24px 与间距 / 等价入口等例外，不能把所有小于 44px 的目标直接判为 AA 失败。参照 [WCAG Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。建议 `/impeccable adapt`、`/impeccable distill`。

**I11，P2，压力模拟复现：200% 字号挤压导航和月报数字。** 390px 下将根字号从 16px 改为 32px 后，旅行 / 月报逻辑宽度扩到约 413 / 436px；固定底栏文字被挤压，月报三列数值与单位重叠。截图已人工核对，不能因 `scrollWidth == innerWidth` 就宣称通过，手机浏览器可能缩小整个布局。位置：`v2/app/mom-reports.css:87`–`:90` 与全站底栏规则。数字、单位可换行或改成单列，底栏高度随文字变化，并给内容预留相应空间。这是 CSS 文字放大模拟，仍需真实浏览器缩放补验。建议 `/impeccable typeset`、`/impeccable adapt`。

### 长文应能随时知道位置并继续阅读

**I07，P2，结构与效率：月、月报、地图需要就近捷径。** 密集月约 22,091px 桌面 / 19,940px 手机；月报有多个内容段落。月份 H1 后直接进入大量 H3，周日期是普通文字；月报在共享 main 内又有 main。现有周链接、日页返回锚点有效，应保留，不能重复提“没有月份导航”。改善是：周 H2、日 H3、媒体子标题合理降级；月报按 3–4 个阅读任务提供就近目录；旅行给地图 / 旅程直接入口。位置：`v2/components/month-timeline.tsx`、`v2/components/month-day-entry.tsx`、`v2/app/mom-reports/page.tsx:72`、`v2/app/layout.tsx:44`。建议 `/impeccable layout`、`/impeccable distill`。

**I09，P2，生产视觉：最新旅程留下空的大图框。** 桌面和手机都能看到完整空照片区域；页面仅有两张实际封面图且均加载成功，因此不是坏图或尚未加载。位置：`v2/components/travel-atlas.tsx:167`，`:168` 在没有 cover 时仍保留固定比例外壳。缺少已授权封面时使用文字明信片或收起照片区，不补虚构影像。建议 `/impeccable harden`、`/impeccable layout`。

**I10，P2，生产交互：地图 Tab 语义与键盘模式不完整。** 点击“美国”能正确切换，ArrowRight 不将焦点移动到下一 Tab。Tab / Enter 仍提供操作路径，因此没有把地图判作完全不可键盘使用。位置：`v2/components/travel-atlas.tsx:118`。实现 roving tabindex、方向键、Home / End 与面板关联，或按实际行为使用普通按钮组。建议 `/impeccable harden`。

### 内部工作台的访问要先关好

**I04，P1，生产访问风险：`/inbox` 匿名可读。** 当前列表为空，没有证据候选已泄露；该页直接读候选且没有身份门槛，后续写入即可能公开内部候选。位置：`v2/app/inbox/page.tsx:31`。生产默认关闭，或使用服务端管理员认证。不要只移除导航。保留 capture / preview 的生产开关。建议 `/impeccable harden`。

健康公开读取有同版源码记录的既往批准，本次不将“可以匿名访问”自动认定为未经授权。健康写入依赖同源 Origin 和自报录入人，不能替代身份认证；如收紧写入与原件访问，应作为明确的审批范围执行，避免自行推翻既有公开决定。普通媒体 original 样本被拒绝，private 媒体不能通过一般公开交付路径读取，这是应保留的保护。

影片实际 duration 372 秒、1080×1920；播放时观测到时间推进与解码帧，定位到 180 秒后已等待 seeked。至少在该帧可见烧入文字，不能因 `textTracks=0` 宣判没有字幕，也不能因此宣称全片字幕与听感合格。日页视频在播放器就绪后通过自定义按钮播放，观测到时间推进、57 个解码帧、原生 controls、全屏及退出；月份展开后可见视频操作入口。这些是 Chromium 证据，逐段音画、真机 / 微信 WebView / 电视体验仍需专项验收。

## 认知负荷和使用者风险

健康一次要求读者理解 8 项图例、年份、横向轴和统计假设，主要问题是需要在图例与记录之间记忆对应关系；宜分成区间性质 / 记录类型并提供记录列表，而不是隐藏资料。月报长文与地图故事入口则需要就近定位。

- 第一次来看档案的家人，可能把历史月报“最近 / 当前”理解为此刻状态；日期说明应贴近相关内容。
- 单手看手机、随时被打断的家人，需要可点中的健康入口、长文目录和恢复位置。
- 键盘 / 读屏使用者需要一致的弹层焦点、照片放大入口和周 / 日标题层级。

没有发现需要改成更商业化、更多渐变或更多动效的理由。改善的情绪目标是减少健康阅读的推算歧义、减少迷路，保留首页生活照片与原话的温暖。
